# MJVBDV2 接入问题记录

更新日期：2026-09-20

本文记录影响 MJVBDV2 替换现有 solver 的机制问题、证据和验证边界。布料、软体不在本次范围内。“对齐”指更换 solver 后行为接近，不等于程序正常退出，也不等于某个任务偶然成功。旧 solver 指 Newton 后端的 `mujoco_warp`；Default 后端的对照会单独注明。

**当前接入已打通主要接口和状态生命周期，但尚不能作为保持原有抓取控制方式不变的通用替代。最关键的限制是：VBD 物体的接触反力不回传给 articulation。** 针对物体标定夹爪目标可以改善部分任务，不能补齐这一机制。

## 1. 单向耦合改变了位置夹紧的工作方式

MJVBDV2 混合模式中，MuJoCo 推进机器人关节，VBD 推进自由刚体。机器人在 VBD 中是按给定姿态运动的碰撞代理，VBD 对物体计算的反力不会传回机器人。

在具有双向接触响应的系统中，夹爪位置驱动允许把目标设得比物体允许的开口更闭合。手指被物体挡住，位置误差继续产生驱动力，驱动力与接触反力形成平衡。因此，“没有到达夹爪目标”可以是正常夹紧状态，并非控制失败。

当前单向路径没有这个平衡：被抓取的 VBD 物体无法阻止手指闭合。手指仍受自身驱动、力矩限制和 MuJoCo 可见接触影响，但缺少这件物体的反力。当两指间隙小于物体尺寸时，VBD 只能尝试移动或转动物体，可能出现穿透、挤出、滑转或抖动。

已有直接证据：同一抓取命令下，旧 MuJoCo 的手指被物体挡在约 0.012 m，新路径则继续到约 0.036 m。这些数值是关节位置，不是夹口宽度。调小闭合目标后能够恢复部分抓取，但控制命令已经改变。

**影响与边界：**

- 依赖“过闭合目标＋接触反力”的位置夹紧控制，不能直接沿用；物体负载对机械臂的反作用也缺失。
- 增加摩擦、迭代或减小步长，可以改善现有接触求解，无法产生缺失的反力回传。
- 按尺寸标定闭合目标只是一种场景适配，会对几何、姿态、碰撞余量和控制误差敏感，不能视为通用闭合策略。
- 若要求保留原有接触驱动的控制行为，需要让这类接触具有双向动力学响应，例如由同一求解器处理，或采用经过稳定性验证的双向耦合。简单延迟一帧回传力并不自动保证稳定。
- 根据接触主动停止闭合属于另一种控制策略，也不能完整恢复物体对机械臂的负载反馈。

这是已确认的结构性限制，但不能据此把所有任务失败都归为同一个原因；场景几何和规划问题仍需独立排查。

## 2. 动态刚体的加入会改变 articulation 的接触路径

纯 articulation 与静态地面场景可以走纯 MuJoCo 分支。加入 VBD 动态刚体后，原生混合分支关闭 MuJoCo 接触，同时又不回传 VBD 反力，因此即使新增物体在远处，也可能让机器人失去地面支撑。这是求解路径变化，不是机器人控制参数突然失效。

本地实验补丁把混合模式的 `disable_contacts` 默认改为 `False`，保留 `use_mujoco_contacts=True`，恢复了 MuJoCo 紧凑模型内的机器人、静态环境及允许的 articulation 间接触。**它实际启用了 MuJoCo-Warp 和 Newton 两套碰撞管线，偏离原生 V2 混合模式的接触配置。**

自由刚体仍不进入 MuJoCo 模型，VBD 侧机器人仍不接收反力，所以双管线不等于同一对接触重复施力，也没有解决第 1 节的夹紧限制。不过，两套管线带来的开销、参数差异和查询范围需要分别处理；本方案尚不是确认后的最终架构。

若要求只使用 Newton 碰撞，同时保留 articulation 的接触响应，需要把合适的接触映射给 MuJoCo 求解。当前 V2 尚未接通此路径，直接设 `use_mujoco_contacts=False` 会被拒绝。

另外，独立 kinematic 物体不会自动进入上述 MuJoCo 接触模型。固定设施可按真实用途声明为 static；真正运动的 kinematic 物体不能用这种替换来解决支持缺口。

## 3. 同名接触参数并不代表相同的物理作用

切换求解器后，必须核对参数实际被谁消费，不能只看配置值相同：

| 参数或机制 | 当前差异及影响 |
| --- | --- |
| 接触余量 margin | MuJoCo 原生 NATIVECCD/MULTICCD 路径会把相关形状的非零 margin 清零，VBD 仍保留；接触建立和释放时机可能不同。启动警告反映真实参数变化，隐藏警告不等于修复。 |
| 扭转、滚动摩擦 | 当前 VBD 刚体接触不读取独立的扭转、滚动摩擦系数，不能照搬 MuJoCo 的相应约束。多个接触点的切向力仍可产生抗转力矩，不等于完全没有抗转能力。 |
| 滑动摩擦、刚度与阻尼 | VBD 接触对的滑动摩擦取几何平均，刚度和阻尼取算术平均；应比较最终接触对，而非只比较手指字段。 |
| 接触阻尼 kd | 当前硬接触中主要抵抗相互接近的法向运动，不是通用的切向止滑或角阻尼。 |
| friction_epsilon | 当前默认刚体硬接触路径不消费该项，修改它不会改变这条路径的摩擦。 |
| 刚体 linear_damping / angular_damping | 现有 Newton 路径中的这些旧属性只保留记录，没有等价施加到运动上；关节驱动 damping 则实际参与求解。此限制也影响旧 Newton MuJoCo，不能归为 V2 独有回归。 |

这解释了为什么复制旧参数不能保证行为相同，但不意味着全部差异都能靠调参消除。尤其是摩擦和接触阻尼无法替代双向反力。

## 4. 接触观测尚未形成统一的力反馈接口

| 路径 | 已确认能力 |
| --- | --- |
| 纯 MuJoCo | 已适配形状编号映射，可查询接触几何、法向及摩擦冲量，并做过行走数值对照。 |
| 混合模式 | 可查询接触几何，但尚未统一合并 MuJoCo 与 VBD 接触，也未提供与纯分支等价的冲量、力反馈。占位零值不能解释为真实无力。 |

“查到碰撞”不等于“有可用于控制或奖励的接触力”。冲量换算为力需要使用对应物理子步时长，不能使用策略更新间隔。即使未来能查询 VBD 接触力，查询接口本身也不会使它回传给 articulation。

另有两项观测限制：

- 当前 Newton 的 `get_qf()` 在位置驱动下读的是直接输入的力矩命令，不包含 PD 实际输出。全零结果不能证明电机力矩一致，也不能直接用于能耗奖励；这不是 V2 独有问题。
- 部分混合接触记录出现零法向且伴有非零约束乘子。这些条目不能用于推导穿透或物理力；尚未确定异常产生于碰撞生成、读取时机还是内部处理，也未证明它是任务失败的原因。

## 5. 接触容量与碰撞成本影响正确性和可用性

VBD 单刚体接触容量与 MuJoCo 的接触、约束容量是不同配置。容量不足会截断参与求解的接触，不只是降低性能；仅扩大 MuJoCo 缓冲区不能解决 VBD 溢出。密集接触验证已观察到单刚体需求超过默认 64，扩大到 256 后完整运行无溢出，但受载滑转仍存在。因此不能用发生截断的结果推断单向耦合的能力上限，也不能把扩容当作夹持问题的完整修复。

性能方面，在双臂、桌子和两个动态物体的初始场景中，关闭窗口、排除规划与录像并完成预热后，同样 20 个子步下，推进 0.08 秒仿真：旧 MuJoCo 约需 0.10 秒，V2 约需 0.38 秒。CUDA Graph 已启用。阶段测量显示主要瓶颈为 Newton 的 GJK/MPR 凸体精细碰撞，每个子步重复执行会放大成本。

这是特定场景的步进测量，不是全任务平均值或所有场景的固定倍率。优先方向是检查碰撞对过滤和凸体复杂度；降低子步数需要重新验证接触效果。本地已准备该 demo 从 20 降到 5 的改动，但尚未完成完整速度和效果复验，不在本次文档提交内。

## 6. 资产、规划与执行差异必须从 solver 差异中分离

已有对照发现以下问题会同时影响新旧 solver：

- 单凸包重新读取 GLB 时采用了不同坐标约定，造成外观和碰撞几何不一致。本地导入补丁改为使用已导入顶点；仅检查画面不够，还需核对实际碰撞形状。
- 初始穿透、物体尚未落稳就规划，以及目标姿态或路径与桌子相交，会改变抓取初态或阻挡机械臂。双臂同轨迹对照已确认新旧都出现桌子阻挡，不能把此类偏差全归为 VBD。
- 缓存轨迹、重新规划、不同夹爪命令、释放等待和播放时序会改变实验条件。增加等待或改变目标后成功，是适配结果，不能宣称原控制命令直接替换已对齐。

因此验证应分别报告：相同输入下的物理差异、适配后的完整任务效果，以及重复运行或初态变化下的稳定性。两边都失败不代表自动对齐，一次成功也不代表稳定兼容。

## 已修复的接入问题

以下补丁解决了接口或状态同步错误，不改变单向耦合的基本性质：

| 类别 | 已完成处理 |
| --- | --- |
| 内部 MuJoCo 访问与编号 | 接通内部 solver，适配 mimic、接触形状编号和 reset。 |
| 状态所有权 | 限制 FK 更新范围，避免旧关节状态覆盖 VBD 自由刚体位置；修正运动代理姿态保留。 |
| 历史状态 | 瞬移和 CUDA Graph 预热回滚时同步内部历史，避免物体异常续移。 |
| 接触缓冲区 | 关闭 MuJoCo 接触时保留必要的非零容量，避免特定摩擦路径除零；这与后续额外开启接触是两项不同改动。 |
| 场景生命周期 | 适配部分／全部 reset，以及同名资产删除重建，支持连续 episode。 |

## 验证结论与未覆盖范围

- **行走：** ANYmal-C 与静态地面／平台已有正常行走和接触反馈对照，同动作关节位置最大差约 1.1e-6 rad，足端法向力分量最大差约 0.015 N，与旧 solver 自身重复差异同量级。纯 MuJoCo 路线与混合路线必须区分；混合地面支撑结果依赖额外开启 MuJoCo 原生接触，不能作为原生混合配置已对齐的证据。未验证 PPO 从零训练收敛、完整生产 reward/done 或复杂地形。
- **操作：** 抓起、倾倒、放置和托盘搬运已有完整改善结果；纸杯搬运、装配、双臂放置、舀冰等仍未完成稳定对齐。剩余问题涉及夹持与释放机制、几何／路径和基线稳定性，不能概括为“几个 demo 参数没调好”。
- **Default 对照：** Slide 采用两后端相同的有效关节阻尼后已通过用户效果验收；这不是旧 Newton MuJoCo 与 V2 的严格数值对照。
- **暂未完成：** Twist 按要求跳过，其早期结果未严格固定完整动作序列；NeuralPlanner 缺少匹配模型。通用刚体约束和 USD 完整物理导出属于既有 Newton 支持缺口。

历史覆盖包括 15 项内置原子技能、18 个原子教程和 26 个其他 Newton 示例入口。不是所有入口都完成任务，也没有覆盖所有机器人、初态与规划器组合。后续补丁只做了针对性复测，不能把早期覆盖数量当作最新版本的全量通过率。
