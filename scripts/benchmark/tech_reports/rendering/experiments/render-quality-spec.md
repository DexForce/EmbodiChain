## 1. 要回答什么

同一场景、相机和画质设置下，两套平台的颜色、深度、分割结果有什么误差？阴影、反射和物体边缘有什么差异？同一配置复制到多个环境后，图像是否仍然一致？

交付 40 个固定视角的原始输出、参考数据、逐视角指标、误差图和质量配置。沿用 [加载实验 Spec](../../loading/experiments/loading-experiments-spec.md) 的资产，直接修改现有相机示例；离线脚本计算指标。

## 2. 场景与视角

| 场景 | 内容 | 20 个视角的分配 |
| --- | --- | --- |
| 工作站 | L-04 W20：Franka、工作台、托盘、20 个零件。保留原始 visual 与材质 | 8 个环绕全景、4 个俯视、4 个遮挡／边缘近景、2 个阴影、2 个反射近景 |
| 工作间 | L-05 U100：房间、家具、Franka、100 个异构物件，保留贴图 | 同样分配；近景覆盖货架、桌面、柜体与机器人 |

位姿从加载实验保存的场景复制。冻结物体和机器人状态，不运行物理步；相机切换只触发渲染。主测不加入玻璃或透明物体，避免不同深度／分割定义混入；源资产有透明材质时，在两端同时改为不透明并另存测试资产。

全景机位按目标点周围每 45° 一个方位生成，再剔除穿墙、被家具挡住或看不到目标的机位，并在测量前补齐 8 个。工作站建议目标 `(0.8,0.5,0.85)` m、半径 1.5 m、视点高 1.5 m；工作间以房间中心为目标，视点保持在室内。其他机位手动确定一次，保存 eye／target／up 与相机矩阵，两平台读取同一份文件。

阴影和反射近景使用同样的光照、材质；需要补充金属板时，两场景各放一块 200×200 mm 金属板，roughness=0.15、metallic=1，位置在试跑前固定。不能只为某个平台改灯光或挑机位。

主分辨率为 640×480，建议 `fx=fy=600、cx=320、cy=240`，near=0.01 m、far=30 m。统一针孔相机，关闭畸变、景深、运动模糊、自动曝光和动态分辨率；超分辨率关闭。记录实际抗锯齿、降噪、光追、阴影和反射设置，不把两平台同名档位当作同画质。

## 3. 先做标定

另外建立一个简单标定场景，不计入 40 视角：灰阶／彩色平面、5 个已知三维标志点、不同距离的平面、两个互相遮挡的方块。分三个视角验证：正视、斜视、部分遮挡。

1. **投影。**统一相机坐标为右方 +X、下方 +Y、视线 +Z；两平台 API 的轴和四元数顺序在写入时转换。按已知三维点报告投影残差、系统偏移及像素定位的不确定性。不要靠移动输出图像补误差。
2. **像素中心。**参考射线采用 `(u+0.5,v+0.5)`；若原生 API 使用另一约定，转换内参并记录。图像统一为 `[H,W,C]`，检查上下翻转及 RGB/BGR 顺序。
3. **深度。**统一为以米表示的轴向 z。若原生输出是射线距离 r，使用 `z=r/sqrt(1+((u+0.5−cx)/fx)²+((v+0.5−cy)/fy)²)`。用中心与边角像素的已知平面距离验证，不能仅看中心像素。
4. **分割。**给家具、物体及机器人 link 分配稳定 ID；背景为 0。读取原生 ID 对应关系后映射，不用彩色可视化图反推 ID。两个互相遮挡的方块用来检查可见表面和标签定义。
5. **颜色。**用灰阶和色块检查曝光、gamma 和 tone mapping。主输出统一到同一 sRGB 显示空间；不能恢复被裁掉的高光时，标明该 RGB 配置无法与线性参考严格对齐。

Isaac 相机同时存在射线距离与轴向深度输出，应按锁定版本选择并校准，不能统一叫 depth 后直接相减。[Isaac 相机文档](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/py/source/extensions/isaacsim.sensors.camera/docs/index.html)

发现坐标、单位、像素中心或标签对应错误时先修正测量链路；转换含义核对后，平台自身的投影／深度偏差仍是待报告结果。保存残差和测量不确定性；不足以分辨平台差异时说明限制，不以任意分数判断标定成功。

## 4. 参考数据怎么生成

### 深度与分割

从共同源资产取得 **visual mesh**，按冻结位姿合并到参考场景；不使用简化 collision mesh。用独立的 trimesh／射线求交工具生成每像素首个表面命中及对象 ID，按同一像素中心、裁剪范围和相机矩阵计算轴向 z。参考求交从 near 裁剪面开始，取裁剪区间内首个有效命中，不能只把 near 前的第一命中删掉而遗漏后方表面。两端统一背面剔除和材质双面属性，参考求交遵守相同可见面规则。保存工具版本、资产哈希、几何及生成脚本。

方块、平面的解析距离先用来验证参考工具。场景中每个 visual 子网格都要进入参考，不只取机器人 link 的第一块 mesh。背景射线为无命中；小于 near 或大于 far 的结果按两端统一裁剪规则处理。

### RGB

先将同一场景导入离线 Blender Cycles，作为独立参考。转换保持 mesh、UV、贴图、材质参数、灯具位置和尺寸；保存 `.blend`、转换说明、Blender 版本与色彩设置。灰阶标定确认灯光强度和曝光换算，不能逐张图调亮度。

建议固定采样 1024 spp，关闭自适应采样和降噪，避免降噪抹掉细节。先对标定及阴影／反射的 6 个代表视角比较 1024 与 2048 spp：报告参考间 LPIPS 与线性 RGB 归一化 RMSE，将参考波动与待比较的平台差异并列；若参考波动会改变比较结论，统一提高采样后复查，仍难分辨时不作优劣结论。保存采样数和随机种子。[Cycles 采样说明](https://docs.blender.org/manual/en/3.6/render/cycles/render_settings/sampling.html)

材质或灯光无法等价转换的视角仍保留，但 RGB 只报告两平台之间的图像差异和定性观察。参考渲染是数值参照，不是真实世界照片；不能凭其得分直接声称某平台更真实。

## 5. 怎么采集

1. 保存配置、资产和静态状态，完成第 3 节标定。
2. 为每个视角设置相机，并重置渲染积累及历史缓存，避免上一个视角残留。
3. 固定丢弃前 32 次曝光；RGB、depth、seg 从同一次保留曝光获取。若版本中历史收敛较慢，试跑时调整所有视角统一的预热次数。
4. 保存 3 次独立采集：每次新进程，完成相同预热，每视角保存 5 个连续帧。主 RGB 指标逐帧计算后汇总；另报同视角 5 帧之间的噪声／变化。不要只挑最好的帧或先平均消噪后算主分数。
5. 同一 GPU 交错运行两平台，主测用 RTX 5090。图像先等待对应渲染队列完成，再读取 GPU／CPU 缓冲区。

RGB 保存无损 PNG，depth 保存 float32 NPZ／EXR，seg 保存整数数组和 ID 映射；另存相机、渲染设置、视角编号、曝光编号与静态状态。失败输出保留原因，不能生成空白图填数。

物理状态不变时，depth／seg 理应稳定；重复帧若发生变化，记录变化像素，不把它当作可忽略的渲染噪声。RGB 随机采样的 5 帧也不能当成 5 个独立场景样本。

## 6. 指标与对比

| 指标 | 计算方法 |
| --- | --- |
| RGB SSIM | 同一 sRGB 空间的 float `[0,1]` 图，data_range=1，11×11 Gaussian 窗口、σ=1.5、总体协方差；按 RGB 通道计算 |
| RGB LPIPS | 固定预训练 AlexNet、LPIPS v0.1、eval 模式，输入 RGB `[−1,1]`，保存 backbone 和线性权重哈希 |
| 深度 RMSE／P95 | 在参考有效像素上计算轴向距离误差；RMSE、绝对误差 P95／max 均以 mm 报告 |
| 深度覆盖 | 参考有效像素中，测试结果有限且在裁剪范围内的比例；缺失像素单独计数 |
| 分割 IoU | 每对象 `intersection/union`；以两图中出现的对象 ID 的并集计算宏平均，漏检或多检对象计 0，背景单列 |
| 边缘误差 | 以参考分割边缘向两侧扩张 2 px，分别报告边缘带与非边缘区的深度／IoU；同时保留全图结果 |
| 阴影／反射细节 | 预先固定 128×128 或更大 ROI，输出同尺度原图、参考、差异图与局部指标，不为不同平台移动裁剪框 |
| 同视角波动 | 5 帧 RGB 的逐像素标准差及指标范围；depth／seg 变化像素比例 |

SSIM 设置按 [scikit-image 文档](https://scikit-image.org/docs/stable/api/skimage.metrics.html)固定；LPIPS 的输入与预训练设置按 [官方实现](https://github.com/richzhang/PerceptualSimilarity)固定。缩放、颜色校正和图像配准仅在标定阶段确定；评分时不做每图拟合。

深度 RMSE 在参考有效区域中测试也有效的子集计算，同时必须展示缺失率。低 RMSE 需结合覆盖率解释；整片区域不输出深度时，保留缺失范围及原因，不能据有效子集宣称全图精度高。参考无命中但测试有深度的像素另报“多报率”。

每视角先汇总 5 帧，再汇总 3 次独立采集，最后按场景报告均值、中位数、最差视角和范围。两平台按同一视角配对。工作站／工作间、参考可比／仅图像差异、全图／边缘区分别列出；不拼成一个总分。

标定与复杂场景均报告实际指标、样本分布和最差视角，不设置统一 SSIM／LPIPS／深度／IoU 合格线。只有具体应用提供容差时才附条件统计和来源，并对两端使用相同定义；连续指标仍为主结果。

## 7. 多环境一致性

工作站与工作间分别预选全景、边缘、阴影、反射 4 个视角，在 N=16 复制场景，全部环境都配置相同相机，各做 3 次独立采集、每次 5 帧。相机外参使用环境局部坐标；背景和灯具也按相同方式复制，环境间不能互相投影、遮挡或产生阴影。

每个环境与自己的 N=1 结果比较：depth／seg 可见像素的一致性、RGB 差异是否超出 N=1 本身的采样波动。分别报告非边缘深度差异和标签一致率，边缘单列。不同环境串标签、位姿偏移或纹理丢失须定位并记录；无法保持相同输入内容时，性能结果只能作为带内容差异的独立测量。

主集共 `40视角×3次×5帧×2平台=1200` 次曝光；多环境组共 `8视角×16环境×3次×5帧×2平台=3840` 张曝光结果。每次曝光同时包含 RGB/depth/seg，不计成三帧；参考渲染和标定另计。它们是质量采集量，不是帧率成绩。

## 8. 实现与交付

参考 create_sensor.py（历史源码：`scripts/tutorials/sim/create_sensor.py) 和 [Camera.update](/home/oem/code/EmbodiChain/embodichain/lab/sim/sensors/camera.py:236`）。当前输出为 RGBA uint8、depth float32、mask int32；额外补齐原始数据落盘、标签映射和视角循环。渲染与数据读取使用同一相机曝光，不连续调用多次渲染来分别取三个通道。

交付：资产／相机／渲染配置、标定结果、40 视角及 batch 原始数据、参考 `.blend` 和几何参考、指标 CSV、全景对比与固定近景。CSV 每行对应一个平台／视角／采集／帧／环境，含参考是否可比、有效率、各指标和失败原因。

图表可脱离仿真引擎从原始文件重新生成。向渲染性能实验提供配置编号及对应误差、覆盖率和波动数据；画质设置、分辨率、资产或相机变化后重新验证。正式采集前先用标定三视角、工作站一个全景和一个反射近景跑通流程。
