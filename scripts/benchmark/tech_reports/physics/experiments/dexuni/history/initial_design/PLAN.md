# DexUni 操作与多材料耦合技术报告：任务设计

状态：实验设计草案，未运行。本文是 Franka 单臂与 W1 V030 双臂实验的共用计划；具体任务说明位于本目录各任务子目录的 README。尺寸、材料、轨迹和阈值为试跑起点，正式比较前冻结；任务难度按操作流程划分，不代表已经跑通。

## 1. 报告目标与实验组织

单臂任务 S01–S03 使用 Franka Panda 与标准二指夹爪；S04 双侧夹取与双臂任务 M01–M05、C01–C02 使用 W1 V030 与双 Pika 平行夹爪，构建简单、中等、复杂三档、共十一项可解释且可复现的操作任务。同一任务在 DexSim/DexUni 和 Isaac Lab 两侧使用相同机器人与末端配置。报告围绕五个问题展开：

1. 软体在小变形时能否稳定响应，在大变形时能否完成抓取并恢复？
2. 薄布是否能抓起、悬垂、单次对折，以及夹持预叠四层布完成搬运？
3. 刚体边缘、软体与多层布料接触时，是否发生可测穿透、面片交叉或失稳？
4. 同一场景中刚体、软体和布料是否真实共同作用；双向组中，载荷是否影响动态机器人？单向组仅展示操作与物体响应。
5. 在上述质量要求满足时，运行耗时、显存和并行吞吐如何？

“展示能力”通过任务完成和量化证据体现；更快、更准确、零穿透均不能作为先验结论。十一项任务共用材料和物体库，机器人按单臂/双臂分组；不同机器人之间不直接比较任务耗时来推断算法优劣，不要求第一轮同时完成全部参数组合。

## 2. 已核对的资产与实现依据

### 2.1 机器人与夹爪配置

| 任务组 | 机器人 | 末端 | 配置要求 |
|---|---|---|---|
| S01–S03 单臂 | Franka Panda | 标准 Panda 二指夹爪 | 两平台共享同一 URDF、手指碰撞网格、TCP、驱动和限力设置 |
| S04 双侧夹取、M01–M05 和 C01–C02 双臂 | W1 V030 | 左右 Pika 平行夹爪 | 核验本地夹爪型号与 Pika 装配，冻结左右安装变换和指尖 TCP |

Franka 可复用仓库现有 Franka 资产加载与抓布示例；指定同一源资产及 hash 后再导入两平台。现有运动学示例不代表动态 two-way 已验证。Pika 如需扩展到 Franka，作为独立末端配置验证，不与标准夹爪结果混算。以下本地资产检查记录针对 W1。

- 已检查 `/home/oem/下载/assets/w1-030/robot.urdf`：包含 V030 躯干、头部、双臂和双侧 GripperCamera 二指模块；24 条非固定关节记录，其中 2 条为 mimic，按 URDF 约束为 22 个独立控制坐标。所有引用的网格文件存在。此检查不等同于动力学验证。
- 本地 `robot_with_ee.urdf` 为 20 条活动关节记录的裸机描述，但当前文件中 21 个网格路径无法解析，不能直接把它当作可运行入口。本文不修改这些用户资产。
- EmbodiChain PR #820 的查询快照：open，head `8d349662417a82fd6a23e26aacece5f976462981`。该 PR 提供标准 V030 裸机、法兰 TCP 和 FEP 配置；Pika 不在已注册的 W1 夹爪品牌中。PR 自述的 IK 结果只证明对应裸机运动学，不证明夹爪装配和动力学。
- 因此目标配置明确为“V030 本体 + 左右 Pika 夹爪”。本地 GripperCamera 是否与指定 Pika 同型号尚未确认。应先核对夹爪源 URDF、安装变换、指尖碰撞形状和 TCP；确认一致可直接复用，否则通过已有末端装配层接入指定 Pika。
- 两平台从同一冻结本体与夹爪源资产导出场景，保留质量、惯量、mimic、限位和碰撞几何。不同来源不能只凭名字相同视为同资产。
- 夹爪开口由指尖实际几何标定，不能将 URDF 中每指 0.05 m 的关节行程直接当总开口。effort=10 的含义和实现也要核验；不能据此声称已经测到 10 N 夹持力。

### 2.2 可复用能力及其限制

- DexUni 现有动态 W1 抓取示例可复用驱动、IK 和软体创建流程；现有双臂折衣、布袋示例可复用几何与任务分阶段方法。
- 现有折衣示例采用运动学回放；部分袋装示例含 pin、高摩擦或分阶段材料调度。它们不能直接作为本计划动态双向、自由抓取测试的结果。
- 主组按 §3.4 分配耦合方式：预计低风险的小规模任务使用动态关节和显式 two-way；多层布和多物体装袋先采用 one-way。单向组可作为正式能力展示，但不证明机器人受载反馈；所有模式均需试跑确认。
- 当前完整表面接触路径具有边/面反作用汇集能力，但本计划每类接触组合的实际覆盖范围仍须逐项检查，不能宣称任意 cloth/soft/rigid 组合均已验证。
- `surface-fast` 仅适用于满足条件的纯表面模型。含四面体软体的混合场景不得标注为使用该加速路径；记录有效配置和回退结果。
- 软体/布料需要 CUDA；粒子接触不等于 rigid ContactQuery。实际逐接触力/冲量没有公开读数时标 unavailable，不能用接触刚度乘位移代替实测力。

## 3. 共用实验场景

### 3.1 场景布局

两组均采用 Z 向上、X 朝工作台、Y 朝机器人左侧的右手坐标，单位 m/kg/s。W1 组世界原点取底盘中心投影，底盘固定，躯干与头部保持冻结姿态，仅驱动双臂和夹爪。Franka 组将固定底座安装面置于 `(0,0,0.86)`，与台面等高；底座位于工作台后方独立安装支架，避免与桌面碰撞。两组分别保存机器人基座到世界的变换。

工作台建议范围 `x=[0.20,0.80]`、`y=[-0.50,0.50]`，台面高度 `z=0.86`；该高度来自现有动态 W1 示例，只是起点。Franka 与 W1 分别进行可达、碰撞和驱动验证，不能沿用另一机器人的关节轨迹或 TCP。任务区域中心 `x=0.48`。以下任务坐标以台面为零高度，写作 `(x,y,h)`，换算为世界 `z=0.86+h`；Franka 安装面等高后，相对底座的任务高度即为 h。

- 双臂共用区：`x=[0.35,0.65]、y=[-0.25,0.25]`。
- 左臂输入区：中心 `(0.43,+0.22)`；右臂输入区：中心 `(0.43,-0.22)`。
- 双臂停车姿态与工具碰撞包络提前固定。每条轨迹均先检查可达、自碰撞、桌面干涉和关节/驱动限位。
- 纯物理组只保留桌面、必要夹具和任务物体；技术报告视频使用相同物理场景，可增加 render-only 背景。

软材料先使用同一弹性模型，起点 E=30 kPa、ν=0.35；具体本构及阻尼以两侧可对齐的实现为准。软梁可在独立 pilot 中选较柔软档，之后锁定，不在正式运行时临时调参。布料分别校准拉伸、剪切、弯曲与阻尼；物理厚度、碰撞厚度、粒子半径独立登记。默认无塑性、破裂和黏附。M05/C01 的软包单独启用闭合腔体气压；开口购物袋和普通布片不启用气压。

起始接触摩擦设定以 0.6 为目标，记录最终各接触对的实际混合值和混合规则。跨平台支持不同本构或不同网格时，明确分为质量配平比较或 N/A，不写“严格同物理输入”。

压板抓取柄建议截面 20×20 mm、高 50 mm，与底板为同一刚体；指尖夹住柄的两侧，不能让夹爪与底板/软块先发生干涉。总质量和惯量从完整几何确定。单臂任务核对 Panda 夹爪，双臂任务核对 Pika 的实际开口、指长与受载预算。

每个 episode 先静置至少 1 s，再以实际稳定状态建立高度、宽度和位置参考；若 1 s 内未稳定，按预先规定的最大静置时长处理并记录。变形率相对于该参考状态计算，同时保存未受载静止网格，避免把重力沉降当作压缩量。

### 3.3 控制和时间

外层控制 60 Hz，先尝试每帧 10 子步，再做 5/10/20 子步收敛。每项任务在两平台共享对应机器人的关节目标文件、夹爪目标、速度/effort 限制、驱动公式和重力补偿。Franka 使用其对应 IK；W1 可用 PR 的 FEP 或现有 IK 离线规划。正式对比读取同一份已检查的任务轨迹，Franka 与 W1 分别规划和标定。

抓取使用真实指尖接触，不焊接物体、不把顶点 pin 到手、不临时关闭物体碰撞，也不在松爪时突然改摩擦。诊断组若使用附着或固定夹具，需单列标签。阶段边界、初始静置时间和超时写进配置。

正式试跑前检查受载预算：物体重力、压缩所需载荷、夹持摩擦与机器人驱动限值必须相容。尤其 S01 的手持压板既要产生下压力又要防止抓取柄滑脱。先用独立压缩台架估计所需载荷，再选择可执行的目标档；超过预算的档记为任务配置不可达，不归因于求解器，也不能为达成目标临时增大夹持摩擦或驱动上限。

### 3.4 按性能风险选择耦合方式

采用用户确认的原则：预计低风险的配置优先双向耦合，存在明显性能风险的配置先用单向耦合。下表是基于接触规模和任务目标的初始设计，不是已测得的“无风险”结论；风险按具体网格、并行环境数和求解设置评估，不能仅凭任务难度下结论。

- **双向主组**：`coupling="two_way"、joint_mode="dynamic"`。机器人接收物体接触反馈，目标与实际位置均保存。S04 的接触限位闭爪、M04 的受阻运动仅在该组解释。
- **单向主组**：`coupling="one_way"`，不设置非空 `coupling_options`。机器人按已冻结的合理关节轨迹和夹爪开口操作；首选复用可验证的运动学回放控制路径，并显式记录 `joint_mode="kinematic"`。单向不要求关节必为运动学，如用 dynamic 也需独立记录，不能将两者混为一个开关。
- 单向的含义是机器人运动影响物体，物体反作用不返回机器人。布—软体—刚体之间的相互作用、自碰撞、重力和气压仍保持任务所需物理，不能为加速一并关闭。
- 单向组不能继续使用“目标完全闭合，由接触反力让手指停住”的控制/验收。预设开口需按物体和夹指几何独立试跑，固定后再测；不能在运行中读物体宽度后直接写回物体位姿、施加附着或取消碰撞。测任务完成、滑移和物体变形，不报告机器人受载停住、力平衡或反馈精度。

| 任务 | 初始主组 | 初步风险判断与模式理由 |
|---|---|---|
| S01-C/T | 双向 | 单个软体、简单夹具接触；需要区分真实材料形变和夹持滑移 |
| S02 | 双向 | 单软块抓放；需要接触阻挡、夹持保持与实际变形 |
| S03 | 双向 | 单片布抓角，基准网格较小；61/121 网格和多环境另评风险 |
| S04 | 双向 | 现有动态夹取参考；限力闭爪停在物体上是核心观察 |
| M01 | 双向 | 单根软梁、双端抓持；基准规模受控 |
| M02 | 双向 | 单布单折、两层接触；基准网格先测，细网格另评风险 |
| M03 | 单向 | 四个独立布层、多层摩擦与自碰撞，接触规模与收敛风险较高 |
| M04 | 双向 | 单布与固定平顶、接触区域小，且需要机器人受阻观察；低延展高刚度仍需单独检查收敛和耗时 |
| M05 | 双向 | 单个闭合软包与刚块，顺序操作；若气压/接触成本明显上升再单列单向组 |
| C01 | 单向 | 购物袋、刚体、体积软体和气压软包同场景，接触种类多且长序列累积成本高 |
| C02 | 单向 | 袋壁自碰撞、袋框连接、两件载荷与提袋，先保证可复现的几何操作 |

**试跑与模式调整**：先固定单环境、基准网格、动作、材料、时间步和计时范围，记录质量结果、每段耗时、显存采样和有效求解器设置。预计低风险组通过后再扩大网格和环境数。目标耗时/显存预算在试跑配置中登记；没有预算和计时结果，不写“已无性能风险”。

若双向需要反复增加耦合轮数/子步，或超出冻结预算，先确认开销来自反馈耦合还是 VBD/气压/自碰撞。只有前者占明显成本时，单向才可能缓解；不能预设单向一定更快或能修复数值发散。需要时按用户已确认原则另建单向运行配置，并同步移除受载反馈结论。S04/M04 若改为单向，只能作为物体操作/接触展示，不算完成其双向反馈验证。

**计时与结果分组**：同一 episode 全程使用一种耦合模式，切换模式用新 run_id，不在中途静默切换。直接测耦合开销时保持两组 `joint_mode="dynamic"` 和其他输入一致；若同时改成运动学轨迹回放，报告的是整套执行配置差异，不能只归因于耦合。跨平台速度主图只比较反馈语义和任务质量对齐的组，单向/双向以及 dynamic/kinematic 分开列。现有 `test_dexuni_coupling_model.py` 可作为隔离计时的参考，但简单夹爪基准不能替代各完整任务的性能验证。

### 6.3 无穿透和多层布的附加验证

用户关注的无穿透仍保留为报告目标，但证据分级：

1. 第一轮记录桌面内节点下穿、M04 解析棱台内部节点量和固定角度视频。解析量可由现有坐标读数计算，但统计脚本仍需实现与校验；报告范围限定为相应节点几何检查。
