## 1. 报告目标与实验组织

单臂任务 S01–S03 使用 FR3 + Franka Hand；S04 双侧夹取与双臂任务 M01–M05、C01–C02 使用 W1 V030 与双 Pika 平行夹爪，构建简单、中等、复杂三档、共十一项可解释且可复现的操作任务。同一任务在 DexSim/DexUni 和 Isaac Lab 两侧使用相同机器人与末端配置。报告围绕五个问题展开：

1. 软体在小变形时能否稳定响应，在大变形时能否完成抓取并恢复？
2. 薄布是否能抓起、悬垂、单次对折，以及夹持预叠四层布完成搬运？
3. 刚体边缘、软体与多层布料接触时，是否发生可测穿透、面片交叉或失稳？
4. 同一场景中刚体、软体和布料是否真实共同作用；双向组中，载荷是否影响动态机器人？单向组仅展示操作与物体响应。
5. 在上述质量要求满足时，运行耗时、显存和并行吞吐如何？

“展示能力”通过任务完成和量化证据体现；更快、更准确、零穿透均不能作为先验结论。十一项任务共用材料和物体库，机器人按单臂/双臂分组；不同机器人之间不直接比较任务耗时来推断算法优劣，不要求第一轮同时完成全部参数组合。

### 2.2 可复用能力及其限制

- DexUni 现有动态 W1 抓取示例可复用驱动、IK 和软体创建流程；现有双臂折衣、布袋示例可复用几何与任务分阶段方法。
- 现有折衣示例采用运动学回放；部分袋装示例含 pin、高摩擦或分阶段材料调度。它们不能直接作为本计划动态双向、自由抓取测试的结果。
- 主组按 §3.4 分配耦合方式：预计低风险的小规模任务使用动态关节和显式 two-way；多层布和多物体装袋先采用 one-way。单向组可作为正式能力展示，但不证明机器人受载反馈；所有模式均需试跑确认。
- 当前完整表面接触路径具有边/面反作用汇集能力，但本计划每类接触组合的实际覆盖范围仍须逐项检查，不能宣称任意 cloth/soft/rigid 组合均已验证。
- `surface-fast` 仅适用于满足条件的纯表面模型。含四面体软体的混合场景不得标注为使用该加速路径；记录有效配置和回退结果。
- surface-fast 报告口径：在统一场景、网格、物理材料、控制轨迹、时间步、子步及CUDA Graph配置下，对比DexUni surface-fast与普通VBD的求解策略，属于求解器级优化比较。基础迭代数、自适应回退、Jacobi/Chebyshev、多层校正和缓存均属于求解策略的组成部分；不同策略的一次迭代不等价。性能与任务效果分别按实测指标说明，不能仅因基础迭代次数不同而将结果解释为单纯减少迭代。“统一配置”不表示所有平台/SDK版本或求解器内部开关完全相同；仍逐项披露实际版本、有效路径、接触和耦合差异。
- 软体/布料需要 CUDA；粒子接触不等于 rigid ContactQuery。实际逐接触力/冲量没有公开读数时标 unavailable，不能用接触刚度乘位移代替实测力。

## 3. 共用实验场景

### 3.1 场景布局

两组均采用 Z 向上、X 朝工作台、Y 朝机器人左侧的右手坐标，单位 m/kg/s。W1 组世界原点取底盘中心投影，底盘固定，躯干与头部保持冻结姿态，仅驱动双臂和夹爪。Franka 组将固定底座安装面置于 `(0,0,0.86)`，与台面等高；底座位于工作台后方独立安装支架，避免与桌面碰撞。两组分别保存机器人基座到世界的变换。

工作台建议范围 `x=[0.20,0.80]`、`y=[-0.50,0.50]`，台面高度 `z=0.86`；该高度来自现有动态 W1 示例，只是起点。Franka 与 W1 分别进行可达、碰撞和驱动验证，不能沿用另一机器人的关节轨迹或 TCP。任务区域中心 `x=0.48`。以下任务坐标以台面为零高度，写作 `(x,y,h)`，换算为世界 `z=0.86+h`；Franka 安装面等高后，相对底座的任务高度即为 h。

- 双臂共用区：`x=[0.35,0.65]、y=[-0.25,0.25]`。
- 左臂输入区：中心 `(0.43,+0.22)`；右臂输入区：中心 `(0.43,-0.22)`。
- 双臂停车姿态与工具碰撞包络提前固定。每条轨迹均先检查可达、自碰撞、桌面干涉和关节/驱动限位。
- 纯物理组只保留桌面、必要夹具和任务物体；技术报告视频使用相同物理场景，可增加 render-only 背景。

### 3.3 控制和时间

外层控制 60 Hz，基准每帧 10 子步，诊断做 5/10/20 子步。两侧驱动公式、增益、effort/速度限制、armature、mimic 与重力补偿均显式冻结，并从模型/执行路径读回。

**新主驱动契约：`zoh_position_zero_velocity`。** 每个外层帧设置同一个 q_target；本帧全部物理子步保持它，qd_target 显式为 0。EC 不再用旧 `RealtimeJointTargetControl` 的子步插值+速度前馈去对比 Isaac 的位置保持。这里定义的是待实现契约；脚本尚未修改驱动，G1 未通过。若需要插值+速度前馈，必须在两侧实现完全相同的子步公式，另建 control_contract_id 并验证，不与主组混算。

控制分为两组，必须分别记录，不能在一张等输入速度图中混用：

1. **matched_replay（正式物理/收敛/等输入性能主组）**：离线生成并检查每个初态对应的 q_target、qd_target、夹爪目标、时间与阶段数组；两侧读取同一份文件与 hash。达到形变目标不能触发临时改轨迹；不达标就是该运行失败。子步/Graph 对照复用同一外层轨迹，不能把闭环阶段长度变化当作求解器误差。
2. **matched_policy（能力展示辅助组）**：同一闭环规则、参考状态与滤波定义，各侧实测反馈可产生不同目标和阶段时刻。实际目标必须保存；只能报告同策略下的任务表现/系统耗时，不声称同一物理输入或据此反演材料准确性。旧 S01 属于该组且还存在底层驱动不一致。

先做无接触手臂/夹爪探针：在每个物理子步保存真正送入求解器的 q/qd 目标、时间和关节 ID，验证它们按预先登记容差一致；不能以控制器 AST 哈希代替。动态 qpos/qvel 跟踪误差与输入等价性分开，实际状态允许引擎差异。

抓取使用真实接触，不焊接物体、不把顶点 pin 到手、不临时关闭碰撞，也不在松爪时突然改摩擦。阶段边界、静置、最大静置、稳定阈值和超时须先冻结。稳定性判断至少覆盖参考窗内高度/材料线波动与节点速度；未稳定不得强行取参考值作为通过结果。

正式试跑前检查物体重力、形变载荷、夹持摩擦与驱动限值是否相容。材料台架须明确边界条件与理论适用性，先验证参考响应与收敛。旧 S01 台架 40 迭代约 0.37/0.41 mm，而无摩擦线弹性估算为 2.87 mm，尚不能证明 E=30 kPa 的响应。未通过时只能标 `geometry_demo`，不得进入材料准确性或等物理质量主加速图；不能为保留速度图临时取消材料门槛。

压板卡口/导向壁和开局已夹持属于独立夹具设计；可以保留为已声明的压缩台架，但不是自然抓取柄全过程的证据。S01-T 的 15% 夹具预压和指垫 shape μ=1.4（混合后 1.0）是候选设计，评审后固定；不在正式运行内调整。超过受载预算记任务配置不可达，不归因求解器，不临时增大驱动/摩擦。

### 3.4 按性能风险选择耦合方式

采用用户确认的原则：预计低风险的配置优先双向耦合，存在明显性能风险的配置先用单向耦合。下表是基于接触规模和任务目标的初始设计，不是已测得的“无风险”结论；风险按具体网格、并行环境数和求解设置评估，不能仅凭任务难度下结论。

- **双向主组**：`coupling="two_way"、joint_mode="dynamic"`。机器人接收物体接触反馈，目标与实际位置均保存。S04 的接触限位闭爪仅在该组解释。
- **单向主组**：`coupling="one_way"`，不设置非空 `coupling_options`。机器人按已冻结的合理关节轨迹和夹爪开口操作；首选复用可验证的运动学回放控制路径，并显式记录 `joint_mode="kinematic"`。单向不要求关节必为运动学，如用 dynamic 也需独立记录，不能将两者混为一个开关。
- 单向的含义是机器人运动影响物体，物体反作用不返回机器人。布—软体—刚体之间的相互作用、自碰撞、重力和气压仍保持任务所需物理，不能为加速一并关闭。
- 单向组不能继续使用“目标完全闭合，由接触反力让手指停住”的控制/验收。预设开口需按物体和夹指几何独立试跑，固定后再测；不能在运行中读物体宽度后直接写回物体位姿、施加附着或取消碰撞。测任务完成、滑移和物体变形，不报告机器人受载停住、力平衡或反馈精度。

| 任务 | 初始主组 | 初步风险判断与模式理由 |
|---|---|---|
| S01-C/T | 双向 | 单个软体、简单夹具接触；需要区分真实材料形变和夹持滑移 |
| S02 | 双向 | 单软块抓放；需要接触阻挡、夹持保持与实际变形 |
| S03 | 双向 | 单片布抓角，基准网格较小；61/121 网格和多环境另评风险 |
| S04 | 双向 | 现有动态夹取参考；限力闭爪停在物体上是核心观察 |
| M01 | 双向 | 单根软梁、双端抓持；基准规模受控 |
| M02 | 单向 | 单布单折、两层接触；运动学关节回放（用户确认改为单向，不报告机器人受载反馈）；基准网格先测，细网格另评风险 |
| M03 | 单向 | 四个独立布层、多层摩擦与自碰撞，接触规模与收敛风险较高 |
| M04 | 单向 | 原始 W1/Pika 夹爪从完整矩形桌面夹起参考 T 恤下摆，向领口对折一次；无附加夹爪板，衣服初始全部在桌面内，无额外支撑，kinematic + surface-fast |

**试跑与模式调整**：先固定单环境、基准网格、动作、材料、时间步和计时范围，记录质量结果、每段耗时、显存采样和有效求解器设置。预计低风险组通过后再扩大网格和环境数。目标耗时/显存预算在试跑配置中登记；没有预算和计时结果，不写“已无性能风险”。

若双向需要反复增加耦合轮数/子步，或超出冻结预算，先确认开销来自反馈耦合还是 VBD/气压/自碰撞。只有前者占明显成本时，单向才可能缓解；不能预设单向一定更快或能修复数值发散。需要时按用户已确认原则另建单向运行配置，并同步移除受载反馈结论。S04 若改为单向，只能作为物体操作/接触展示，不算完成其双向反馈验证。

**计时与结果分组**：同一 episode 全程使用一种耦合模式，切换模式用新 run_id，不在中途静默切换。直接测耦合开销时保持两组 `joint_mode="dynamic"` 和其他输入一致；若同时改成运动学轨迹回放，报告的是整套执行配置差异，不能只归因于耦合。跨平台速度主图只比较反馈语义和任务质量对齐的组，单向/双向以及 dynamic/kinematic 分开列。现有 `test_dexuni_coupling_model.py` 可作为隔离计时的参考，但简单夹爪基准不能替代各完整任务的性能验证。

### 6.2 从主报告指标中移除的项目

- 接触力、应力、摩擦传递效率、从动作反推摩擦系数：当前没有本任务所需的通用粒子接触力读数，不列主指标。
- 体积偏差、单元 Jacobian/翻转率、中心线曲率：部分可由拓扑与状态离线计算，但并非本任务完成所必需，第一轮移除，避免为指标增加无关实现。
- 自动层数/层序正确率、最小层间距：目前无现成测量实现；M03 已知四个独立布句柄可统计每层运动，但不据此声称层间完全无交叉。
- 通用穿透深度、边面穿越事件数、子步零穿透：公开刚体接触查询不能代替粒子几何检查，主表不承诺这些现成读数。
- 实时气压、漏气率：现有公开创建描述提供压力输入，但本计划未找到通用实时内压/漏气读数，不列主指标。
- 精确袋口面积、软体质心、复杂覆盖率：主表改为框定义区域、节点几何中心和固定标记点，不给缺少定义的百分比。

### 6.3 无穿透和多层布的附加验证

用户关注的无穿透仍保留为报告目标，但证据分级：

1. 第一轮记录桌面内节点下穿、M04 一次 T 恤对折的标记位移与碰撞检查、固定角度视频。报告限定于实际实现并验证的离散几何检查。
2. 布—刚体、布—软体、布料自碰撞如要给定量结果，需要从公开节点/布三角拓扑和创建时碰撞几何构建独立检查器。`Cloth.get_triangles()` 可提供拓扑；网格坐标、节点映射、拓扑邻接排除、接触厚度和几何容差须先核验。检查器目前未实现，标为附加分析而非已支持指标。
3. 检查器需用已知“分离、接触、交叉”的小网格验证。帧级无交叉不证明子步间没穿过；没有子步采集或连续检测就不写连续无穿透。
4. 正式文字限定为“在所述采样和检测下未发现超过容差的交叉/穿透”；只有视频时不写“零穿透”。

参考示例的桌面下穿容差为 4 mm；小变形 task 的 1–2 mm 不能直接写成已达精度。各任务统一公布检测定义、实际最大值与冻结容差，容差不随正式结果临时放宽。

## 7. 对照、规模与原始数据

### 7.1 跨平台公平性

**统一求解器规则（适用于全部十一项任务及其子项）**：Isaac Lab 统一使用 **Newton 中的 MuJoCo Warp + VBD** 组合；DexSim 统一使用 **DexUni 求解器**。Isaac Lab 侧不得改用 PhysX、MuJoCo CPU 或 DexUni 私有实现替代该对照组合；DexSim 侧不得改用其他求解器替代 DexUni。

Newton 对照中使用 MuJoCo Warp 处理机器人/刚体分支，VBD 处理布料/体积软体分支；具体物体归属、分支耦合与气压能力以固定版本的实际支持为准并记录。各任务的单向/双向分组不变，但这不是允许更换求解器的理由。任一任务在指定组合中缺少对应能力时，该格标记 N/A/能力缺口并说明，不用更换后端或替代物补齐。

每次运行须记录 Isaac Lab、Newton、MuJoCo Warp、Warp 与 DexSim/DexUni 的版本/源码提交及实际求解器路径，区分配置请求与实际执行。不支持的耦合模式或数据读数同样标缺口，不能当作语义对齐的速度比较。

原报告记录的 Isaac Lab 提交 `ffff603eafc6b74264a5261cc0183d6a65390d78` 仅作版本溯源，当前尚未核验它是否具备本次指定的 Newton MuJoCo Warp + VBD 组合。正式对照先确认满足新规则的版本并冻结；不能沿用原提交名称，却实际切换到其他物理后端。

两侧共用冻结机器人/夹爪、刚体、模拟网格、材料台架、初态与控制输入。能够共享网格但本构不同，仍需单列差异；不支持共同任务的格标 N/A，并保留可完成的子任务。每项只要求其实际涉及的接触组合：C01 为购物袋—刚体/体积软体/充气软包及商品间接触，并包含气压膜；C02 包含袋壁自碰撞与布—框连接。M05 还需充气膜—刚块/桌面接触及气压支持。缺失不能用刚体替身代替软体，也不把未涉及的软体—软体接触当成任务准入项。

先做无机器人材料台架：软体压缩恢复、布条悬垂/衰减、多层静置、粒子/表面对刚体碰撞、布—软体接触冒烟验证。正式任务前冻结容差和控制，不针对失败平台改成不同任务。

### 7.2 冻结矩阵、独立重复与计时

- 第一轮每任务 10 份具体初态（s00 标称 + 9 份扰动），保存实际数组，不能只保存种子；它们仅作初筛。
- 粘滑/偶发失败另做同初态重复：S01-T 至少选 s00、旧失败 s02、扰动 s05，每侧每状态 10 次；不与“10 个不同初态”混为同一统计量。保留置信区间/事件频次，10/10 对 9/10 不作可靠性优势结论。
- 网格/形变/子步先单变量。几何、总质量、本构、初态、控制组别与检测容差必须一致或明确披露差异。
- N=1 的 G0–G6 和质量通过后，再做 N=8/32，N=128 为容量扩展。复杂任务不保证装得下，OOM 进入完整记录。
- 每计时格 pilot 至少 3 个独立进程；主图 10 个。同机交错平台和轮换先后顺序，准确记录 GPU 型号/显存/驱动，不跨卡算加速比。
- 预热包含编译、懒初始化和图捕获，时长/次数在矩阵开始前固定；预热后恢复完整冻结物理/控制状态并核验。若恢复触发 recapture，先完成它，不能计入首个正式窗口。旧 CSV 的 1.3–1.5 s 首帧不得混入稳态平均，也不能事后任意挑选稳定帧。
- 同步计时至少分 `cold_start`、`init_compile_capture`、`completed_step`、`control_readback`、`capture`、`serialization`、`end_to_end`。记录每项起止边界；粒子读回在 step 之后就必须另计，不能声称 step 包含它。
- 主吞吐用同步完成的固定工作窗口计时；逐帧强同步曲线仅作诊断，单列开销。公开 step 吞吐与纯求解器时间分开，不能把封装和调度差异全部归因于算法。
- 显存独立测量，预热状态、renderer、观测和保留数据范围一致；进程采样值注明间隔与测量覆盖，不以整卡占用或 allocator 子集冒充进程总显存。
- Graph/direct 成对检查实际图状态和相同 replay 下的任务/状态差异。只有 matched_replay、材料/任务质量准入、同语义且同计时边界的格进入主加速图；其它结果保留但 speedup=N/A。

**分母从计划矩阵而不是结果目录得出。** 启动前枚举 matrix_id、cell_id、attempt_id、平台、初态、变体、重复、条件 hash 和超时。worker 启动前登记 planned/started；父进程保留返回码、信号、OOM/超时/缺失，不依赖 worker 能写出 manifest。

正式首轮分母固定：支持该条件的计划尝试中，任务失败和运行错误均不能删除；同时分别报告任务完成率、运行完成率和计划覆盖率。unsupported/preparation_failed 单列原因，不虚构算法测量。重跑产生新 attempt，不覆盖原失败，不自动选最新成功；诊断重复与正式首轮分开呈现。零成功、缺失、未运行格仍出现在表中。

### 7.3 数据与报告图

每个 matrix_id 保存在 `outputs/benchmarks/dexuni/<matrix_id>/`，包含启动前冻结的矩阵、输入/代码身份、gate 证据、attempt 日志与配置；每次尝试使用唯一 run_id。其下 `raw_data/<benchmark-id>/<platform>/<run_id>/` 保存原始状态、目标与实际轨迹、timing、图像和日志；`results/<comparison_id>/`、`videos/<comparison_id>/` 保存派生数据。此为新正式格式设计，旧 adapter 的 flat raw_data 仍仅用于 development。

归档必须包含完整源码快照或 commit+完整未提交 patch（包括未跟踪源码），不能只保留 diff hash；冻结全部资产/转换 payload、网格/材料/初态/控制文件的 SHA256。公共机器人沿用原资产仓库；报告专用输入若将来发布到 HF，按 `assets/DOWNLOAD_DESIGN.md` 的真实 bundle 和完整 dataset commit 校验，只下载选中输入，不自动下载结果/媒体。本次没有可宣称已发布的 bundle 或下载 CLI。

每个 run 记录 requested/effective solver、coupling、joint_mode、control_contract_id、matched_replay/policy、schema/protocol revision、失败阶段和 readout availability。时间/控制序列保存真实单位。借用状态在下一 step 前复制；原始文件只读，离线重建引用冻结 run IDs，不读取当前工作树的控制器 AST 作历史证明。

图像采用预先检查的两个可见视角（优先顶视+斜视；被手遮挡可固定为 front45/side45 并说明）。存储 640×480 RGB/depth/seg、K/外参和每帧真实 simulation_time/physics_frame；可 1280×960 渲染再降采样并同步 K。正常 30 Hz 图像与额外关键帧不得混为固定节拍视频索引。合成按统一时间轴重采样，两侧画面、阶段、帧率注释引用实际时刻；短片结束后标 ended。保留原始时间戳及输出到输入帧的映射。仅有视频不称连续零穿透。

完整采集和性能分别运行，记录采集开销。正式每个比较写一个 Markdown 报告，保留既有三表：Time & Memory、Success & Other Metrics、Leaderboard；未达到条件的 rank/speedup 标 N/A、显示失败/缺失原因。下面各任务曲线作为附图/plotting data，不能替代完整分母表。

报告建议包含：

1. 十一任务总表（S01-C/T 分开列子项）：难度、能力覆盖、coupling/joint_mode、完成率、失败原因、数据链接。
2. S01-C/T：压缩/拉伸恢复曲线；S02：搬运阶段高度与放置目标误差；S04：手指位置、宽度与提起高度；M01：中部下垂。
3. M02：单折标记点对齐；M03：四层分别提起/搬运/放置结果；M04：T 恤下摆翻折轨迹、释放后形态及碰撞检查。
4. C01：刚体、体积软体、充气软包三件商品逐阶段装袋结果；C02：持框装填结果。
5. M05：软包放置与压载前后中央标记高度、刚块底面高度及漂移。
6. 所有任务：质量—耗时曲线；代表任务：规模—吞吐/显存曲线。
7. 成功与典型失败的同时间点图像，不只展示最好的一次。
