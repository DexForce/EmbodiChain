## 1. 共同做法

复用 [加载实验 Spec](../../loading/experiments/loading-experiments-spec.md) 的资产，机器人使用同一份 Franka 模型。基础动力学直接建简单场景，操作实验修改现有 demo。两平台分别运行，离线脚本计算连续误差、任务事件和图表。评价原则见[总览](simulation-report-spec.md#评价原则)。

### 输入与物理设置

- 单位为米、千克、秒，重力 `(0,0,−9.81)`；操作任务建议物理步长 5 ms、控制周期 20 ms，每个控制目标保持 4 个物理步。内部子步、迭代、接触模型和容差单独记录。
- 源 visual／collision、质量、质心、惯量、摩擦、恢复系数、驱动和限位一致。碰撞 margin 与实际几何分别核查。引擎不能表达相同物理模型时说明差异，不只复制同名参数。
- 每个场景保存 10 个初态及实际数组。每次将其中一个复制到 N 个环境，依次执行全部 10 个；环境之间碰撞隔离，N 个复制体不算 N 个独立初态。
- 轨迹在测量前生成，记录关节顺序、时间、关节目标、夹爪目标、阶段和外力。离线检查限位、速度和可达性，两平台重放同一份输入；不在正式运行中分别规划。
- 建议机械臂使用力型位置驱动：Kp=120 N·m/rad、Kd=15 N·m·s/rad，力矩上限取同一源资产值。夹爪主驱动建议 Kp=1000 N/m、Kd=20 N·s/m、上限 40 N，从动指保留原生 mimic。试跑后统一确定；不能一端用加速度型驱动、另一端用力型驱动。
- 操作物体建议质量 0.1 kg，静／动摩擦均为 0.8，恢复系数 0；基础摩擦实验另设参数。固定基座、桌面和托盘一致。
- 测量阶段只写驱动目标或施加已定义的力。直接改实际位姿／速度、清零动力学状态仅用于初态和重置，不出现在夹持、堆叠或插接中。

除 P-05 的 15 s 外，任务窗口为 10 s。场景创建、离线 IK、预热和重置不计入运行吞吐。失败环境仍运行到固定窗口结束并记录状态，不自动换初态或重置为成功；数值错误时停止该运行并记录。

### 先确认数据可用

用两个环境和一个受力刚体完成预检：

1. 位置／姿态、关节、TCP 采用环境局部坐标；检查四元数顺序和对象 ID 不串环境。
2. 验证外力生效周期：给质量已知物体施加恒力，检查速度增量与 `FΔt/m`；停止施力后不残留。关节附加力同样检查。
3. 用平面与已知间隙校准接触距离的符号、单位和是否包含 margin；用静止支撑物核对冲量时间窗口及与重力的关系。
4. 接触只读有效行。容量从 256／环境开始，达到容量则加倍重测，直到不饱和或取得明确 overflow 信息。接触点数量与对象对数量分开记录。

当前部分后端没有完整接触导出，详见第 4 节。没有数据时填“未提供”，不能填零穿透或零力。静态对方 ID 无法区分时，记为未知静态对象，不合并成已知对象对。

## 2. 连续指标与任务事件

| 指标 | 口径 |
| --- | --- |
| 位置 RMSE | 对齐物理时刻后，`sqrt(mean(sum((p−p_ref)²)))`；另报 max／终点误差 |
| 姿态差 | 归一化四元数 `2·acos(clip(abs(dot(q,q_ref)),0,1))`，q 与 −q 等价 |
| 抓持滑移 | `T_rel=inverse(T_TCP)·T_object`；相对夹持参考时刻计算平移及转角 |
| 抖动 | 固定保持窗口的相对速度 RMS、相对位姿峰峰值；漂移另报，不用平滑删除尖峰 |
| 穿透 | 经校准的接触距离或独立几何距离；几何穿透与含 margin 的接触距离分开。报告 max、P95、穿透持续时间及相对尺寸／间隙比例 |
| 接触 | 接触点和唯一无序对象对分别统计；只读有效行。不同 solver 的 manifold 点数不要求相同 |
| 接触力 | 先报原生冲量 J；仅在覆盖时间 Δt 已确定后换成平均力 `J/Δt`，不标成瞬时峰值力 |
| 任务事件／完成次数 | 有明确任务或几何依据时，记录 10 初态中的离桌、释放、掉落、塌落、越限、穿墙等事件；另报全部复制体分布，不扩大独立样本数 |
| 事件时刻 | 保存首次发生、持续时间和恢复时刻；中途事件不因末帧恢复而消除 |

先给出每初态连续指标，再汇总均值／中位数／范围；重复运行的波动与不同初态差异分开。所有复制体均记录极值、任务事件和数值异常。性能图不按任意 9/10 门槛筛点，而是同时展示耗时与误差／任务结果；提前异常中止不当作完成窗口的速度样本。必要指标缺失时说明，N=1 的表现不外推到全部复制体。

基础解析参考不使用另一引擎；操作任务用几何目标、完整时间窗口和状态判定。两端不满足相同物理模型时，以独立参考及自身步长收敛解释，不给模型差异强算速度比。

## 3. 性能怎么测、需要跑多少

### 计时范围

**物理循环：**关闭相机和录制，按 20 ms 更新相同关节目标，以 5 ms 调用 `sim.update(step=1)` 或另一平台对应 API。包含输入写入及主机调用；此时间不能叫纯 solver kernel 时间。

**env.step：**使用两端已有环境，加载同一场景和轨迹，不加入规划。观测统一为 q／qdot、TCP 和目标物体状态，奖励关闭或固定零，成功判定和终止摘要相同；保留完整环境步调用开销。关闭自动 reset，提前失败只记标志，继续到固定窗口。每控制步按上述四个物理步执行，同步记录数量。

当前 BaseEnv.step 一次调用 `sim.update(..., step=4)`，没有逐物理步的外力／判定回调。实验脚本在物理推进位置做局部包装，将该调用拆为 4 次原生 `update(step=1)`：每步先施加 P-03 的外力或 P-06 的阻尼，推进后更新状态与失败摘要；其他实验同样逐步检查保持条件。保留完整 env.step 的其余流程，两端采用相同的推进粒度，包装和状态读取开销全部计入。不新增通用回调框架；先用 4 步预检确认外力、数据时刻和步数，再测速。

如果需要补 env 的任务定义，先用一个最小现有环境验证；暂时没有 env.step 入口的配置标为未完成，不能把物理循环改名当 env.step。

每次独立重复使用新进程：准备场景 → 预热 200 物理步 → 完整 reset 到初态 → 等待 GPU → 测完整任务窗口 → 等待 GPU → 保存。10 个初态逐个 reset、计时，重置时间不进分母。

`物理吞吐=N×完成物理步数/耗时`；`环境吞吐=N×完成控制步数/耗时`。两个步数明确标注，P-05 窗口为 15 s。内部子步开销都包含在调用时间中，但子步不冒充公共物理步。

P50／P95／max 单步延迟另做同配置运行，每个调用完成后同步。吞吐只在整个窗口边界同步，不用逐步同步的结果代表正常批处理吞吐。物理内部／接触／约束时间用可信原生计时；分段同步诊断不混入主吞吐。

准确性 N=1 每物理步保存完整状态／接触；大 N 性能运行在 GPU 上累计所有环境的失败标志和极值，仅保存预定的环境 0 全轨迹。对同输入配置核对诊断／精简记录的关键指标与事件一致，测速后也核查全部环境摘要。

RAM／GPU 每 20 ms 采样，方法沿用加载 Spec。报告采样峰值及基线，PyTorch allocator 不代表总显存。超时／OOM／数值错误留记录，不能降 N 后替换原点；建议单次窗口组超时 20 min，试跑后统一调整。
