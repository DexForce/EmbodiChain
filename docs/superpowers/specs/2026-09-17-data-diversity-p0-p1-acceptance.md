## 1. 本次交付范围

P0 建立可追溯的数据事实，P1 交付可实际使用的本地浏览器分析工作台。
支持 EmbodiChain 仿真扩增采集和当前项目使用的 LeRobot 格式接入。
离线统计、筛选和录制数据回放不能要求启动仿真器或使用 GPU。

六类首批维度为资产、姿态、Affordance、轨迹、材质、光照。以一个既有
抓取—放置任务和一种机器人完成真实接入，优先选 repeated_pick_place
的 Franka 部署。沿用部署文件声明的物理后端，不通过 CLI 切换后端。

真机兼容的含义是接入同格式数据，保留 measured / annotated / estimated /
configured 来源及未知值，不包含真机在线控制或自动补全未知物理属性。

模型评估调度、训练暴露统计采集、性能归因、自动补数执行、训练调度、
多用户权限及集群部署属于后续阶段。本次保留稳定数据版本与关联标识。

### 1.1 技术选型与依赖约束

根据用户的复用要求，采用 Gradio + EmbodiChain Viser + Polars + SQLite。
不另建 React/Vite/ECharts/Three.js 前端工程，不新增 DuckDB、独立 FastAPI
应用或外部数据库服务；Gradio 自身的传递依赖不在此限制之内。

- **工作台入口**：用 Gradio Blocks 构建可独立启动的分析面板，并在现有
  GenSim 工作台增加入口。共享面板与服务代码；独立启动不加载 GenSim
  生成工作流、Blender 或模型服务配置。分析领域逻辑不放进 GenSim。
- **二维分析**：复用 Gradio 原生图表、Dataframe 和项目已有 Matplotlib。
  联合热图下钻可以通过同一数据源的单元格选择实现，不要求自研 JS 图表组件。
  分箱与聚合由分析服务完成，图表只负责展示；所有筛选共用查询状态。
- **三维与回放**：复用 Viser 场景协议、几何/轨迹覆盖层、相机图像和回放
  控件，并沿用现有 Gradio 内嵌 Viser 的模式。新增录制数据适配器，将
  已保存的场景/轨迹转换为显示快照，不通过运行物理仿真重建录制结果。
- **同步机制**：Gradio 处理筛选和 episode 切换；回放控制器维护唯一时间轴，
  同步发布 3D 状态、相机解码帧、阶段和数值。高频回放不通过 Gradio Timer
  逐帧触发整个页面更新，也不依赖两个独立视频播放器自行保持同步。
- **计算与存储**：用项目已声明的 Polars 处理 Parquet 分区和惰性筛选/聚合；
  Python 标准库 SQLite 保存目录、事务性事件账本、作业及保存的切片。
  原始视频保持引用式访问。写入收敛到受控 writer，查询使用已发布快照。
- **生命周期**：分析任务和回放均有明确的会话归属；切换数据、关闭会话或
  应用退出时清理 worker、媒体句柄和 Viser 实例，不影响现有 GenSim 作业。
- **依赖安装**：优先保持项目现有版本约束。独立分析入口声明最小可选依赖组，
  避免为使用 Gradio 被迫安装整个 gensim extra；CLI/统计导入不加载 UI 依赖。
  图表和回放事件以仓库锁定版本实测，不以最新版在线文档代替兼容性验证。
- **离线边界**：当前 `embodichain.lab` 存在提前导入仿真的路径，需要针对
  复用路径调整导入边界并做回归验证；保留原有公开导入方式。不复制第二套
  场景协议来绕开导入问题。

性能和功能门槛保持本文其余章节的要求。单元格下钻不限定某种前端图表库；
替换 UI 方案不能省略视频/状态同步、真实采集或离线运行验收。

## 2. P0：数据事实与血缘

| ID | 必须实现的行为 | 验收方式 |
| --- | --- | --- |
| P0-01 | 六类维度具备版本化定义：类型、单位、参考系、作用范围、来源、缺失原因、适用条件；非法值与未知版本明确报错 | 正反例契约测试；未知与零值统计不同 |
| P0-02 | 区分配置采样范围、运行时实际值和最终入库数据；记录随机化生效时间及全局/环境行作用范围 | 配置范围内只实际采到部分区域时，图表只对实际值计数；共享参数不伪装为独立采样 |
| P0-03 | 稳定标识关联 run、scene case、candidate、attempt、episode、segment、commit；血缘支持多个源片段及变换记录 | 从任一确认入库 episode 追溯源片段与扩增参数；重排环境槽位不改变逻辑身份 |
| P0-04 | 保存候选、规划失败、执行失败、质量拒绝、待写、部分提交、完整提交等可区分状态与原因 | 固定验收样本和故障注入检查各阶段数量；没有数据产出的失败仍可查询 |
| P0-05 | 媒体提交和分析元数据完整性分别记录；只有完整确认记录参与默认有效覆盖 | 注入 sidecar 失败后，记录为部分提交；对账修复后才进入完整覆盖 |
| P0-06 | 重复导入、事件重放、写入重试幂等；同 ID 不同内容不能静默覆盖；索引中断后能重建 | 重放前后 ID 集合、数量和统计一致；冲突报告可定位到源记录 |
| P0-07 | 历史 LeRobot 数据可导入；无扩增元数据时标记 unavailable，不编造血缘或实际随机化值 | 使用完整、新旧元数据和缺字段样本测试；导入不修改原始数据 |
| P0-08 | 配置、资产内容标识、实际初始状态、任务与生成器版本、seed 和轨迹时间/动作契约可关联 | 清单可定位依赖资产和原始帧；明确哪些信息缺失导致无法复现 |
| P0-09 | 分析关闭时不改变原有生成与录制行为；分析失败不能被显示为已成功收集 | 相关录制/扩增回归测试；失败有持久化诊断与明确状态 |

运行时观测是实际分布依据。仅有配置或请求值时，必须保留对应来源标签。
规划轨迹和实测轨迹分开保存；符号效果、预计成功和物理测量成功分开标注。
无源演示的程序生成数据使用明确的生成器来源，不制造虚构父 episode。

## 3. P1：分析与可视化

| ID | 必须实现的行为 | 验收方式 |
| --- | --- | --- |
| P1-01 | 浏览器总览展示候选/失败/完整入库量、独立源家族数、六类维度完整率和分布 | 图表、查询结果和清单计数完全一致 |
| P1-02 | 六类维度均可筛选，至少支持分类多选和连续区间；跨图表共享筛选条件 | 选择资产与姿态范围后，指标、列表、热图和导出同步变化；刷新可恢复保存的切片 |
| P1-03 | 支持资产×姿态、Affordance×接近方向、材质×光照三类二维统计 | 每个单元格可下钻到具体 episode/segment；空缺、不适用和未知分开显示 |
| P1-04 | 覆盖指标绑定明确版本的目标定义、分箱、合法区域和统计单位 | 没有目标定义时显示观测分布，不显示无分母的覆盖百分比 |
| P1-05 | 轨迹可按阶段对齐，显示关节/TCP 路径、时长和速度；几何与时序统计分离 | 同一路径仅改变速度不增加几何覆盖；计划与实际偏差可查看；不同具身配置不能直接混算 |
| P1-06 | 展示资产与 Affordance 摘要；有几何数据时展示交互区域、局部坐标系或接近方向，并关联实际使用的阶段 | 从 Affordance 切片进入具体轨迹；缺少几何时说明缺失，不伪造区域 |
| P1-07 | episode 详情联动时间轴、可用相机视频、状态/动作、轨迹和阶段；支持两条轨迹比较 | seek 后时间与帧对齐误差不超过一个记录帧间隔；无视频时仍能查看状态和轨迹 |
| P1-08 | 比较两个不可变数据集快照的数量、分布、覆盖和近重复情况 | A/B 交换方向后增减含义一致；不同维度定义版本明确拒绝比较或显式对齐 |
| P1-09 | 导出可复现的筛选清单与针对支持维度的扩增配方 | 清单包含稳定 ID、源数据引用、快照及查询定义；配方通过生产配置校验，且能完成一条小规模采样/生成验证 |
| P1-10 | 同一输入和特征版本产生一致统计；新增数据增量处理，版本变化触发所需重算 | 第二次扫描不重新提取未变化的数据；缓存失效测试覆盖源数据和提取器变化 |

P1-09 的默认导出是引用式清单，不复制或重编号整个训练数据集。
扩增配方包含支持的维度范围、目标计数、seed 与来源切片。统计维度到
随机化配置的映射必须显式声明；不可生成的维度组合给出原因，不输出
貌似可执行的无效配置。训练脚本接入与自动补数调度不属于本次交付。

## 4. 固定样本验收

随代码提供独立的小型验收夹具，覆盖正常值、未知字段、无效值、近重复、
多父血缘、断裂引用和部分提交。期望结果来自夹具的显式清单，不能调用
被测聚合函数来生成期望值。

核心账本案例包含 12 个逻辑候选：

- 2 个规划失败，2 个执行失败，1 个质量拒绝，7 个通过质量校验。
- 其中 6 个完整提交，1 个发生媒体已提交、分析元数据写入失败。
- 修复前：候选 12、质量通过 7、完整入库 6、部分提交 1。
- 修复后：候选仍为 12、完整入库 7、部分提交 0。
- 重放同批事件并再次扫描，计数与 episode ID 集合不变。
- 单独的二维覆盖夹具定义 4 个合法材质×光照单元，完整数据覆盖 3 个，
  对应单元覆盖率严格为 75%；未知值不占用第四个单元。
- 轨迹夹具包含相同路径的变速版本，以及明确不同的路径；验证几何覆盖
  不随单纯变速或增加采样频率增长。旋转比较处理四元数正负等价。

## 5. 真实仿真端到端验收

在一个固定部署、一个机器人上运行小规模采集。保存完整配置、实际参数、
环境信息、运行日志和最终清单；至少得到 12 条真实、完整入库的有效 episode。
允许记录额外失败尝试，但必须设尝试上限并公开全部结果，不能无限重试隐藏失败。

资产、姿态、材质、光照各至少覆盖两个实际取值/条件，轨迹至少包含两个
几何路径族；记录真实使用的 Affordance 与任务阶段。Affordance 若只有一种，
图表如实显示单类，交互区域/方向的多样性另行统计，不以换标签制造能力差异。

通过浏览器完成：总览 → 二维切片 → episode 回放 → 血缘追踪 → A/B 比较 →
切片导出 → 扩增配方校验及小规模采样/生成。截图和日志作为交付证据。
旧数据兼容额外使用一份缺少分析 sidecar 的数据进行验证。

真实任务成功使用已声明且记录证据的测量判定器。只有 projected 语义效果时，
不能据此声称物理任务成功；需要补充适合该抓取—放置任务的测量检查。

如果 GPU/仿真依赖使真实验收无法运行，应将这一项报告为未完成，不以 mock
测试或静态页面替代。录制数据分析与回放另在禁止导入 DexSim/仿真启动模块的
进程中验证 CPU 离线可用性。

## 6. 性能与工程验收

以下是完整验收目标；实际测量与范围以本版验收报告为准：

- 使用固定生成种子的 10,000 episode / 100,000 segment 元数据基准；
  六类摘要字段齐全，原始视频和逐帧特征提取不计入查询基准。
- 本地 SSD、单分析进程，记录 CPU、内存、数据体积及版本；已有索引后，
  固定查询组预热一次、测量 30 次，筛选与二维聚合 p95 ≤ 3 秒。
- 索引构建和上述查询峰值 RSS ≤ 2 GiB；浏览器分页加载记录，媒体按需读取。
- 验收报告同时给出首次索引、增量索引耗时和实际仿真采集开销，明确缓存条件；
  页面体验另做浏览器验证，不将后端查询耗时冒充页面响应耗时。
- 新生产逻辑有契约、统计、失败恢复及 CLI/API 集成测试；浏览器关键操作实际验证。
- 运行受影响扩增、录制、CLI 和可视化回归测试；遵守现有 CPU/GPU 测试划分。
- 使用 `black==26.3.1`；提交前运行 `black .`；API 文档覆盖检查及相关项目上下文检查通过。
- 交付可复现启动/接入/导出命令、验收样本、指标口径、性能报告与已知限制。
