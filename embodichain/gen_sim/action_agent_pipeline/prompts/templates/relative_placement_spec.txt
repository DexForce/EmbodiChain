Parse a simple dual-arm tabletop relative-placement task and produce a constrained config-level JSON spec. Deterministic config generation uses this JSON to build executable seed_task_graph_v3, agent_success, and the human-readable task_prompt.txt, basic_background.txt, and atom_actions.txt diagnostic records. Runtime execution grounds the Seed graph from live environment state and does not invoke a second graph-generation LLM.

Return exactly one JSON object with this schema:
{
  "placements": [
    {
      "moved_object": "<source_uid from rigid_object>",
      "reference_object": "<source_uid from scene objects, or moved_object/self for initial-position moves>",
      "goal_relation": "inside|on|left_of|right_of|front_of|behind|front_left_of|back_left_of|front_right_of|back_right_of",
      "arm": "left|right|auto",
      "orientation_goal": "preserve|upright|lay_flat|axis_align",
      "orientation_reference": "none|world_axes|reference_object",
      "orientation_axis": "none|x|y|long_axis|short_axis"
    }
  ],
  "task_prompt_summary": "<one or two sentences for task_prompt>",
  "basic_background_notes": "<short scene/task notes>",
  "action_sketch": [
    "grasp moved_object",
    "move above the relation target pose",
    "place at the release pose with Place"
  ]
}

Rules:
- Use only source_uid values from the scene objects listed below.
- Return one placement for a single-arm task and exactly two placements for a dual-arm task.
- Treat the task as dual-arm when it explicitly says 双臂, 两臂, both arms, two arms, or when it describes separate work for the left arm and the right arm even if it does not literally say 双臂.
- Do not invent a second placement when the task only moves one object.
- moved_object is the object to grasp and move.
- reference_object is the object used as the spatial reference, container, or support.
- reference_object may be a rigid_object or a background object such as a pad, tray, basket, or container.
- For single-object directional tasks such as moving the only object forward, left, front-left, or back-right from its initial position, set reference_object to the same source_uid as moved_object (or 'self'). This means the generator will use the object's initial position as a fixed anchor, not the object's moving runtime pose.
- Within each placement, moved_object and reference_object must be different unless the task is an initial-position directional move.
- For dual-arm tasks, the placements must use two different moved_object values and one left arm plus one right arm. Use arm='auto' only when the user did not specify which arm handles that placement.
- arm selects the single robot arm that should manipulate moved_object. Use arm='left' for explicit left-arm instructions such as 左臂, 左机械臂, left arm, or left robot arm; use arm='right' for explicit right-arm instructions such as 右臂, 右机械臂, right arm, or right robot arm; use arm='auto' when the task does not specify an arm.
- For Chinese/English left/right/front/back, use the relation enums from the rotated robot-view perspective. front_of means positive world-x; behind means negative world-x; left_of means positive world-y; right_of means negative world-y. Diagonal relations combine both axes: front_left_of, back_left_of, front_right_of, back_right_of.
- If the task says to release an object above a basket/container so it falls into it, use goal_relation='inside'.
- If the task says to stack/place one object on another non-container support, use goal_relation='on'.
- orientation_goal captures the held object's intended pose before release. Use 'upright' for tasks like 扶正, 竖起来, or stand upright. Use 'lay_flat' for tasks like 平放, 横放, or lay flat. Use 'axis_align' for tasks like 水平摆正, 摆正, or aligning an object to a pad, box, container, or support axis. Use 'preserve' when no orientation change is requested.
- For axis_align, set orientation_reference='reference_object' and orientation_axis='long_axis' when aligning an object such as a stapler or shoe to the long side of a pad, box, or container. Use orientation_axis='short_axis' only when the task explicitly asks for the short side. Use orientation_reference='world_axes' with orientation_axis='x' or 'y' only when the task explicitly specifies a world/table axis.
- For preserve, upright, and lay_flat, use orientation_reference='none' and orientation_axis='none'.
- Do not return numeric offsets, object poses, scales, success JSON, robot config, or full prompt files. The generator computes those deterministically.
