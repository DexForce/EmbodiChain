# WorldParticle example execution record

Checked on 2026-11-15 at implementation commit
`b0875186ca946f7fbfc56031379d99114d2835ef` (#902, with #822's foundation).
Runtime: Linux x86_64, Python 3.12, Torch 2.11.0+cu128, SDK 0.6.0rc2,
Newton 1.7.0, Warp 1.17.0, NumPy 2.2.6 and RTX PRO 5000 72GB Blackwell (SM120).
The process used one CUDA device and two CPU threads. Open3D
`0.19.0+1e7b1743` and FlashAttention `2.8.3` were the local Torch 2.11 builds
identified in `runtime-manifest.torch211.json`; this was not a clean default
installation of published operator dependencies.

## Full headless inference

All four published checkpoints ran through `WorldParticleProvider` via the
actual `run-example` command, with the default complete step budgets:

| Scene | Particles | Steps | Source initial frame / stride | Result |
| --- | ---: | ---: | --- | --- |
| Fancy Fluid | 7020 | 199 | 0 / 1 | Finite positions/velocities, NPZ/JSON written, normal exit |
| Cloth on Ball | 4900 | 80 | 10 / 1 | Finite positions/velocities, NPZ/JSON written, normal exit |
| Duck forward deformation | 1102 | 15 | 0 / 5 | Finite positions/velocities, NPZ/JSON written, normal exit |
| Deep Fluid | 3528 | 199 | 0 / 1 | Finite positions/velocities, NPZ/JSON written, normal exit |

Prepare/verify all 19 pinned files as in [README.md](README.md), then run from
the repository root in the qualified operator environment:

```bash
python -m embodichain run-example learning/worldparticle demo --scene fancy_fluid --headless --once --hold-seconds 0
python -m embodichain run-example learning/worldparticle demo --scene cloth_on_ball --headless --once --hold-seconds 0
python -m embodichain run-example learning/worldparticle demo --scene inverse_design --headless --once --hold-seconds 0
python -m embodichain run-example learning/worldparticle demo --scene deep_fluid --headless --once --hold-seconds 0
```

Use `--assets DIR` for a prepared location other than the default. The validation
used that option and explicit `--output` paths outside Git. Initial trajectory
state was loaded once; predictions were generated by the solver, not read from
the reference trajectory. Deep Fluid's generated state has no official reference.

## Native offscreen rendering

Each of the four scenes also ran a separate two-step offscreen capture with
the default OfflineRT renderer. Each produced two nonempty 1920×1080 RGB PNGs
and exited normally. Cloth and Fancy Fluid images were visually inspected;
all four output sets had nonconstant pixel values. Reproduce for each scene:

```bash
python -m embodichain run-example learning/worldparticle demo --scene cloth_on_ball --headless --once --hold-seconds 0 --steps 2 --capture-dir outputs/worldparticle/cloth-captures
```

Replace `cloth_on_ball` with `fancy_fluid`, `inverse_design` or `deep_fluid` and
choose a distinct capture directory. Displayless Linux uses the demo's SDL
offscreen path. These checks qualify offscreen execution, not desktop window
interaction, and did not repeat full-length video encoding at this new runtime.

## Other evidence and limits

Earlier source-build checks covered CUDA fixed-radius search, BF16 FlashAttention
against SDPA and all four standalone model calls on a nondefault stream without
Newton/DexSim/Warp/core imports or input mutation. A deterministic predictor
separately checked native force units, rotation, buffers, reset and unsupported
runtime rejection. The manifests retain those earlier two-step/operator records;
the full example runs above supplement them rather than relabel historical
Torch 2.7 results or changing binary hashes.

Finite execution and rendered output do not qualify long-horizon accuracy,
historical-runtime equivalence, native/model numerical parity or bitwise replay.
The unchanged network contains CUDA reductions/hash-neighbor construction with
no established determinism guarantee. No functional-gradient/APG, dynamic rigid
coupling, native contact-force report, CUDA Graph capture or additional GPU
architecture capability is claimed. See [INPUTS.md](INPUTS.md) and the retained
license/provenance notices before applying the model to another asset/domain.
